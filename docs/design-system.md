# Inventory Design System Usage

## Shared class design system

The Inventory prototype must use the class-approved design system used by all eight modules.

The source code archive did not contain the class design-system URL, so this document does not invent a URL. Before final submission, the group should use the exact shared design-system link agreed by the class.

## Inventory-specific application

Inventory does not introduce a new color palette, typography system, spacing scale, radius scale, or shadow style.

The Inventory prototype uses the shared system for:

- navigation;
- buttons;
- form fields;
- tables;
- cards;
- modals;
- alerts;
- badges;
- responsive layout.

## Inventory-specific meanings

| UI element | Meaning |
|---|---|
| Stock In | Adds quantity to current stock |
| Stock Out | Removes quantity from current stock |
| Low Stock | Stock quantity is 10 or below |
| Available | Stock quantity is greater than 0 |
| Out of Stock | Stock quantity is 0 |
| Success | Requested operation completed |
| Error | Operation could not be completed |

The visual treatment of these meanings must use the exact shared class badge/status colors.

## Content rules

Use realistic Inventory content:

- `Pencil`
- `Printer Ink`
- `Bond Paper`
- `Notebook`
- `Ballpen`
- prices formatted as `₱1,500.00`
- dates formatted as `Sep 25, 2026`
- integration IDs such as `INV-00005`

No lorem ipsum or placeholder gray boxes should appear in the final prototype.
